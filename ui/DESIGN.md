# TAŃDA — спецификация интерфейса (Streamlit)

Документ для разработчика (Codex). Цель — реализовать интерфейс **один в один** с макетом. Все размеры указаны для десктопа шириной 1440 px, в CSS-пикселях.

Эталонные файлы макета лежат в `design-reference/*.html`. В них каждый элемент свёрстан с точными inline-стилями. **Если этот документ и эталон расходятся, прав эталон.** Файлы эталона — это не готовый код: теги `<x-dc>`, `<helmet>` и скрипт `DCLogic` относятся к редактору макетов и в проект не переносятся. Брать из них нужно только разметку и стили.

---

## 0. Главные правила

1. **Интерфейс не содержит логики подбора.** Он собирает параметры формы, вызывает `recommend(query)` из `pipeline/recommend.py` (зона лидера) и рисует результат. Фильтрация, ранжирование, тексты объяснений, заголовки и пояснения приходят из пайплайна готовыми.
2. **Никаких заявок, бронирования и звонков.** Нигде нет кнопок «Заказать», «Записаться», «Оставить заявку». Сервис только рекомендует.
3. Все тексты интерфейса на русском. Тексты ниже в «кавычках» — точная копия, её не переписывать.
4. Имена, цены и цифры в макете условные. В коде они приходят из `recommend()`.
5. **Файлы интерфейса лежат только в `ui/` и `.streamlit/`.** Папки `pipeline/`, `data/`, `tests/` — зона лидера, их интерфейс не меняет.

## 1. Стек и структура

Python + **Streamlit** (версия не ниже 1.50). Архитектура проекта задана лидером и не меняется.

```
project/
  pipeline/            зона лидера: load, filters, ranking, explain, recommend
  ui/
    app.py             весь интерфейс: 3 экрана в одном файле
    style.css          все стили, токены в :root
    mock_data.py       заглушка recommend(), пока пайплайн не готов
    DESIGN.md          этот документ
  .streamlit/
    config.toml        тёмная тема Streamlit (нужна для полей формы)
```

Запуск из корня проекта: `streamlit run ui/app.py`.

**Как дизайн сделан в Streamlit:**
- Стили из `ui/style.css` подключаются в начале `app.py` через `st.html("<style>…</style>")`. Стандартная шапка и меню Streamlit скрыты.
- Всё, что просто показывается (шапка, главная, карточки, воронка, «Чуть не вошли», пустые исходы), рисуется своей HTML-разметкой через `st.html` с классами `.t-*` из `style.css`.
- Интерактивные элементы — стандартные виджеты Streamlit, перекрашенные через CSS:
  - плитки мероприятий и категорий, чипы города, бюджета, часов, языка — `st.pills` (иконки — Material Symbols в подписи: `:material/favorite: Свадьба`);
  - дата — `st.date_input`, бюджет — `st.number_input`;
  - кнопки — `st.button` (`primary` — бежевая пилюля, `secondary` — контурная, `tertiary` — ссылка).
- Тёмные рамки и панели — это `st.container(key=…)`: Streamlit добавляет контейнеру класс `.st-key-<key>`, и CSS красит его. Ключи: `hero`, `res_top`, `quiz_panel`, `f_city`, `f_date`, `f_budget`, `f_hours`, `f_lang`, `final_row`, `sug_row`.
- Экраны переключаются через `st.session_state.screen` (`home` / `quiz` / `results`). Ссылки в шапке ведут на `?screen=…`.
- Значения формы дублируются в `st.session_state.form`, потому что Streamlit стирает состояние скрытых виджетов. Благодаря этому при возврате с результата форма остаётся заполненной.

## 2. Данные: контракт с лидером

### Запрос (`query`) — интерфейс собирает из формы

```python
query = {
    "city": "Астана",
    "date": "2026-11-14",          # ГГГГ-ММ-ДД
    "event_type": "свадьба",       # строчными, как в датасете
    "category": "Ведущий",
    "budget": 400000,
    "hours": 5,                    # или None, если «Не важно»
    "language": "казахский",       # строчными, или None
}
```

### Ответ (`result`) — возвращает `recommend()`

```python
result = {
    "outcome": "matched" | "no_category" | "none_passed",
    "headline": "Подобрали 3 варианта",
    "summary": "сколько в категории, сколько отсеяно и почему",
    "cards": [{"id", "name", "categories", "city", "price", "synthetic",
               "score", "score_parts", "explanation", "availability", "notes"}],
    "rejected": [{"id", "name", "reasons": [{"code", "text"}]}],
}
```

### Как поля ложатся на интерфейс

| Поле | Где показывается |
|---|---|
| `outcome == "matched"` и 3 карточки | экран «Подобрали», иконка-галочка |
| `outcome == "matched"` и 1–2 карточки | тот же экран, иконка `info`, блок «Как мы искали» |
| `outcome == "none_passed"` | экран «Никто не подошёл» (п. 9.1) |
| `outcome == "no_category"` | экран «Такой категории нет» (п. 9.2) |
| `headline` | большой заголовок статуса |
| `summary` | текст под заголовком; в пустых исходах — и в карточке «Где отсеялись» / «Почему так» |
| первая карточка в `cards` | тёмная карточка «Лучшее совпадение» |
| `name`, `categories`, `city`, `price` | верх карточки: имя, «Ведущий · Астана», «от 350 000 ₸» |
| `explanation` | текст объяснения |
| `availability` + `notes` | строки с галочками (строка или список строк) |
| `synthetic` | бейдж «Синтетический профиль» |
| `score_parts`, `score` | раскрывающийся блок «На чём основано объяснение» → «Из чего сложился балл» |
| `rejected`, у кого ровно одна причина | строка «Чуть не вошли» (не больше трёх) |
| `rejected` целиком | список «кто и почему не подошёл» в `none_passed`, если нет `funnel` |
| прошлый и новый результат, если поменялась только дата | баннер «Выдача изменилась из-за занятости» (интерфейс сравнивает `id` карточек) |

### Необязательные поля — попросить лидера добавить

Интерфейс уже умеет их показывать, если они появятся. Без них он просто не рисует соответствующий блок.

| Поле | Что даёт |
|---|---|
| `cards[].price_imputed`, `cards[].city_imputed` | бейджи «Цена оценочная — уточните», «Город проставлен при подготовке» |
| `cards[].facts: [{fact, quote}]` | факты с цитатами из описания в «На чём основано объяснение» |
| `result.funnel: [{label, count}]` | воронка «15 → 13 → 9 → 3» и полоски в пустом исходе |
| `result.suggestions: [{label, value, text, button, patch}]` | карточки «Что изменить»; `patch` — например `{"date": "2026-12-13"}` или `{"budget": 1200000}` |
| `result.season_note: {title, text}` | сезонная карточка (без неё интерфейс показывает стандартный текст для декабря) |
| `result.meta: {cached, explanations_verified, fallback_used}` | «из кэша», «Факты сверены», «Объяснения в упрощённом виде» |

### Заглушка

Пока `pipeline/recommend.py` нет, `app.py` берёт `mock_recommend` из `ui/mock_data.py` и показывает на результате пометку «Демо-данные: воронка ещё не подключена». Как только лидер добавит функцию `recommend`, интерфейс сам переключится на неё — менять ничего не нужно.

**Значения по умолчанию при первом входе:** ничего не выбрано, бюджет пустой, часы и язык — «Не важно». Кнопка всегда активна: если чего-то не хватает, при нажатии под пустыми блоками появляются сообщения.

**Проверки перед отправкой:**
- Не выбрано мероприятие / категория / город / дата — под соответствующим блоком красноватым (`--danger-icon`) текстом 13: «Выберите мероприятие» / «Выберите, кто нужен» / «Выберите город» / «Выберите дату».

**Отправка:** пока работает `recommend(query)`, показывается «Подбираем…», затем открывается экран результата. Если функция упала с ошибкой, под кнопкой: «Не удалось получить подбор. Попробуйте ещё раз.»

## 10. Форматирование

- Деньги: разряды через неразрывный пробел, знак тенге через пробел: «350 000 ₸», «от 1 200 000 ₸».
- Даты в интерфейсе словами: «14 ноября 2026», в тексте без года: «14 ноября». В API — ISO `2026-11-14`.
- Время ответа — с запятой: «2,3 с».
- Числа, тексты объяснений, статусы и подсказки форматирует бэкенд; фронтенд выводит как есть (кроме значений в полях формы).

---

## 11. Адаптивность

Основной макет — 1440. Контент растягивается до 1440 и дальше центрируется.

- **≤ 1200:** сетка «Что мы проверяем» 7 → 4 колонки; H1 главной 68 → 56.
- **≤ 900:** все сетки по 3 колонки → 1 колонка; плитки 6 → 3 колонки; сетка условий → 2 колонки; ряды полей формы → 1 колонка; боковые отступы 64 → 20; ссылки шапки прячутся, остаются логотип и кнопка «Подобрать»; «Чуть не вошли» — колонкой без разделителей; воронка в блоке «Как мы отобрали» — с переносом строк.
- **≤ 480:** плитки 3 → 2 колонки; H1 главной 40; кнопки во всю ширину.

---

## 12. Доступность

- Плитки и чипы — настоящие `<button>` с `aria-pressed`; группы обёрнуты в `role="radiogroup"` с подписью (`aria-labelledby` на заголовок блока).
- Поля ввода связаны с `<label>`.
- Видимый фокус у всех интерактивных элементов (обводка 2px `--accent`).
- Статус результата объявляется для скринридеров (`aria-live="polite"` на заголовке результата).
- `prefers-reduced-motion`: отключить все переходы.

## 13. Чек-лист приёмки

- [ ] Главная, подбор и результат совпадают с эталонами по цветам, размерам шрифтов, отступам и скруглениям.
- [ ] На главной нет полей выбора — только объяснение и кнопки в подбор.
- [ ] При незаполненных обязательных полях сообщения появляются у нужных блоков.
- [ ] Список категорий не зависит от города.
- [ ] Результат рисует все исходы: `matched` с 3 карточками, `matched` с 1–2, `none_passed`, `no_category`.
- [ ] Лучшая карточка тёмная, остальные светлые; при 1–2 карточках сетка не растягивается.
- [ ] Бейджи «Синтетический профиль» и «Цена оценочная» видны там, где пришли `flags`.
- [ ] «На чём основано объяснение» раскрывает факты с цитатами.
- [ ] Повтор того же запроса только с другой датой показывает баннер «Выдача изменилась из-за занятости».
- [ ] Кнопки подсказок в пустом результате меняют параметры и сразу повторяют подбор.
- [ ] Ошибка в `recommend()` показывается текстом под кнопкой, а не красным экраном Streamlit.
- [ ] Нигде нет слов «заказать», «записаться», «заявка».
- [ ] Интерфейс читается на ширине 390 px.
